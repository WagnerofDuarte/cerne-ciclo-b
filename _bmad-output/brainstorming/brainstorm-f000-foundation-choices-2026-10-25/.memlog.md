- (technique by coach) started First Principles Thinking
- (idea by coach) Bedrock fact: every repository must return Either Failure T, so the Failure shape should mirror the backend error shape plus exactly one local-only variant for failures that never touch the network
- (idea by coach) Bedrock fact: retryable is a server-asserted flag, so the try-again button logic should render purely on retryable being true, never on client-side guessing from error codes
- (idea by coach) Bedrock fact: session state is binary, valid or expired, so F000 needs exactly one SessionStatus stream that every bloc subscribes to, nothing else independently decides login state
- (idea by coach) Bedrock fact: the vault is 100 percent local, so rebuild it with no async Either plumbing at all, threading a synchronous local decision through the same Either as network calls would be over-engineering
- (idea by coach) Bedrock fact: entries are immutable with no PATCH or DELETE, so the entries repository interface should never expose update or delete methods, not even as unimplemented stubs
- (idea by coach) Bedrock fact: offline allows only viewing cached data, never writing, so write methods like createEntry and sendMessage should have no offline code path at all, no optimistic queueing to reconcile later
- (idea by coach) Bedrock fact: RF08 and RF10 are explicitly described as sharing the same failure-isolation pattern, that repetition in the spec is permission to build one isolatedSideEffect helper used by both instead of two parallel implementations
- (idea by coach) Bedrock fact: PII check and embedding happen inside POST /entries, so the client needs no PII-awareness logic at all, resist adding client-side pre-filtering for safety
- (idea by coach) Bedrock fact: the spec explicitly states no risk-signal detection as a scope decision, so F000 should not add defensive risk-detection hooks just in case, that door is deliberately closed
- (idea by coach) Bedrock fact: design_tokens.dart is the single source with zero hardcoded values allowed, rebuilding from scratch means no screen widget holds even one temporary literal color or number
- (idea by coach) Bedrock fact: no BLoC imports another BLoC directly is stated for RF07 but is really a whole-app pattern, cross-feature communication should be repository or stream level everywhere, not just in the timeline screen
- (idea by coach) Bedrock fact: chat messages never become entries automatically except the explicit RF10 action, so chat and entries should be modeled as genuinely separate aggregates in the folder structure, resisting a shared Record supertype
- (idea by coach) Bedrock fact: the background session timeout is fixed and explicitly not configurable, so it belongs as a hardcoded Duration constant in core, never exposed through Settings even as a hidden toggle
- (idea by coach) Bedrock fact: whisper_ggml never sends audio to the backend, so the RF02 domain use case should take raw audio in and text out with zero awareness of where transcription runs, keeping the constraint enforced by architecture not convention
- (idea by coach) Bedrock fact: the 13 backend error codes are a closed set, so the Failure-mapping function should switch over the enum with no default case, making a hypothetical 14th code a compile error instead of a silent runtime gap
- (insight by coach) Two of the free choices, secure storage and biometrics, are really one decision, the vault, not two independent parameters, worth collapsing in any eventual decision matrix
- (insight by coach) The shared failure-isolation wording for RF08 and RF10 reads as a spec-level hint toward one shared helper, not a coincidence of similar phrasing
