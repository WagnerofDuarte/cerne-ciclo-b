- (constraint) Platform: iOS only, portrait orientation only (requirements.md sec.13). No Android target, no landscape layout work.
- (constraint) Clean Architecture, 3 layers per feature (data/domain/presentation) under lib/features/<feature>/; domain imports neither package:flutter nor anything from data/ (RNF06, AGENTS.md).
- (constraint) State management fixed: flutter_bloc. Error handling fixed: fpdart Either<Failure,T> on every repository signature, no exceptions. Test doubles fixed: mocktail. On-device STT fixed: whisper_ggml (audio never reaches backend).
- (constraint) Backend is frozen and out of scope: every call goes to {FUNCTIONS_BASE_URL}/<x-cerne-function>, never the literal openapi.yaml REST path. apikey header on every call; Authorization: Bearer <anon key> only on signup/login/refresh (security: [] ops); Authorization: Bearer <user token> on every bearerAuth op.
- (constraint) Visual tokens: lib/core/design_tokens.dart is the single source for every color/font/spacing/radius (RNF08); never write a visual value elsewhere.
- (constraint) RF10: chat feature must create entries through a shared interface/use case, never by importing the entries repository or data source directly (violating this also breaks RNF06).
- (constraint) RF07: no BLoC imports another BLoC directly; the auth/sync/data streams it composes combine only through the domain layer.
- (constraint) Entries are immutable once created: no PATCH/DELETE /entries/:id in the backend contract; no screen offers edit or delete of an entry.
- (constraint) Architecture is cloud-only: offline permits viewing already-cached data only, never writing (RF06 AC, generalized across all write endpoints per requirements.md sec.6 note on POST /chat/sessions and /chat/.../messages being "blocked offline").
- (constraint) Sync badge has no server column: computed entirely client-side from Entry.serverRevision + Entry.updatedAt + transient pending-local-write state (sync-badge.md). Server never supplies a sync_status field.
- (constraint) Minimum domain-layer test coverage >=80% (RNF07); 5 write endpoints x 3 failure types (timeout, malformed response, no connection) = 15 scenarios covered by mocktail tests (RNF09).

No relational engine: every query dimension (source/dateFrom/dateTo, semantic search) is a server-side query param per openapi.yaml; the client never filters/joins/sorts cached data itself. - (decision) Cross-feature access contract (new, generalizes RF10's explicit AC): a feature may depend on another feature only through a domain-layer interface (abstract use case / port) that the owning feature defines and registers in DI -- never through the other feature's data/ layer, repository, data source, or BLoC. Binds: RF10 (chat -> entries, via e.g. an abstract SaveEntryUseCase defined in entries/domain, injected into chat's presentation/domain), and any future cross-feature dependency the delivery order introduces. Prevents: a feature reaching into another's persistence/implementation details, which breaks RNF06 and makes the two features' internals impossible to change independently.
- (decision) Shared SessionStatus stream ownership (new): exactly one SessionStatus stream, exposed from the auth feature's domain layer (the feature F000 scaffolds for login/signup), registered once in DI as a singleton. go_router's redirect (F000), RF07's composite auth x sync x data state, and any other feature needing session state all consume this same stream -- none re-implements session detection via ad hoc endpoint polling or try/catch on 401. Prevents: two independently-built screens disagreeing on what "session expired" means or when to prompt re-login.
- (decision) BLoC composition rule (new, generalizes RF07's explicit AC "no BLoC imports another BLoC directly" to all features): a BLoC/Cubit never holds a reference to another BLoC/Cubit instance, in any feature, same-feature or cross-feature. Composing multiple independent streams happens by injecting the underlying domain-layer streams/use-cases into each BLoC independently, or by a parent widget using BlocListener/MultiBlocListener to react to several BLoCs and dispatch events -- never BLoC-to-BLoc direct reference.
- (decision) Offline write-gating rule (new, generalizes RF06 AC's "cloud-only" note and RF04's "blocked offline" writes to every feature): every repository's write operation surfaces Failure.networkOffline when there is no connectivity, rather than queuing it; read operations fall back to the local Hive cache transparently. No feature implements a local write-queue/outbox. Pending-local-write state (used to render the Synchronizing sync-badge state) is transient in-memory state for the duration of the in-flight request, never a persisted queue.
- (decision) Entry immutability rule (new, states explicitly what requirements.md sec.6.2 implies): the entries feature's repository interface exposes create/read operations only -- no update/delete method is ever added, matching the backend's lack of PATCH/DELETE /entries/:id.
