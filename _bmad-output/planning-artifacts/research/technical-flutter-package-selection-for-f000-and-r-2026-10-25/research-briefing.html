The driving pattern across all six: avoid build-time codegen unless it earns its keep. go_router, get_it, and dio each have codegen-based siblings (auto_route+generator, injectable, chopper) that are credible but add a build_runner step a solo developer on a fixed timeline doesn't need yet — every codegen alternative is kept as a named upgrade path, not dismissed.

Second pattern: two of the "obvious" NoSQL picks are traps. Both isar and hive — the packages most tutorials still point to — have their original packages effectively abandoned (last releases 2022–2023); only community forks remain. drift avoids that risk entirely.

Biggest caveat: no cross-package integration friction was tested (e.g. dio + flutter_secure_storage + get_it wired together) — each pick was researched independently. Reasonable to accept given all six are mainstream, popular choices, but it's an open question, not a verified fact.

6. Biometrics — local_auth

Sole credible candidate — a hand-rolled platform-channel implementation was considered and rejected (duplicates the plugin, no documented upside for a solo timeline).
  • Verified flutter.dev publisher, 1.82M weekly downloads [22]
  • NSFaceIDUsageDescription required in Info.plist for Face ID; not required for Touch ID [23]
  • stickyAuth: true resumes in-flight auth on foreground return; false (default) fails immediately on backgrounding [24]. The 5-minute idle-timeout gate (RF03) itself is app-level logic, not plugin-provided.
  • Biometric lockout after repeated failures requires passcode entry to reset — no programmatic reset [23][25].

Cross-dimension insights

  • The codegen-avoidance pattern recurred independently three times (routing, DI, HTTP) despite each dimension being researched in isolation — weak evidence that "skip codegen for now" is the right default for this project's size, not one researcher's bias.
  • The abandoned-package trap was specific to local cache — no other category had a "popular but actually dead" result. A developer going by package-name familiarity alone would likely have picked isar/hive without knowing both are fork-dependent now.
  • Biometrics and secure storage are adjacent but distinct: local_auth gates access, flutter_secure_storage's Keychain accessibility class governs when stored data is readable relative to device-lock state. RF03 needs both wired together at the app layer; neither package solves the other's half.

Open questions

  • Cross-package integration friction (dio + flutter_secure_storage + get_it together) — not tested; resolve during F000 implementation, not more research.
  • go_router's version-to-version API stability complaint [31] — needs a direct read of flutter/packages GitHub issues.
  • flutter_secure_storage's iOS Keychain error codes on restart/background [13] — needs a direct GitHub issues search.
  • provider, manual-constructor DI, and GetX's router were never researched — no evidence either way if reconsidered.
  • riverpod-as-DI-under-flutter_bloc has no current production source evidencing the combination works — reasoned inference only.
